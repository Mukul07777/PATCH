Architecture

Inside the agent.

Nine stages, three models, one rule: nothing ships until the tests pass.

🔌

Connect

Resolves the Nemotron model for each tier from the provider's /models catalog, or uses the ones pinned with MODEL_*.

📦

Check out

Copies a demo case or clones a public GitHub repo with a pinned requirements.txt and a pytest suite.

🛰️

Scan OSV.dev

Every pinned package is queried against the open-source vulnerability database for real CVEs and GHSAs.

⚡

Triage nano

Decides which advisories your code actually reaches, so the plan focuses on what matters.

🔎

Research Tavily

Searches for changelogs and migration guides for each upgrade. The sources are kept as evidence.

🧭

Plan super

Picks the safe target version for each package and flags breaking upgrades.

🧪

Upgrade & test

Installs the new versions in an isolated venv and runs your pytest suite.

🛠️

Repair super → ultra

Failures go back to Super with the stack trace. If it keeps failing, the job escalates to Ultra, up to MAX_FIX_ATTEMPTS.

🚀

Pull request

Green tests produce the diff, the cited evidence and a PR description, and a real GitHub PR if GITHUB_TOKEN is set.

FAQ

Good questions.

Does it change my code or just versions?

Both. When an upgrade breaks an API, the agent edits the call-sites and re-runs the tests until they pass.

What if it can't get the tests green?

The run ends as "needs review". You still get the partial diff, the test output and the research, but no PR is opened.

Which LLM provider does it use?

Any OpenAI-compatible endpoint serving Nemotron: Nebius Token Factory, NVIDIA NIM or OpenRouter. Set NEBIUS_BASE_URL and the key in .env.

Is running untrusted repos safe?

Tests run in a throwaway venv. Remote repos can be switched off for public demos, so only the bundled cases can be run.

Can I audit what the agent did?

Yes. Every event is written to a JSONL log. Open the Runs page to replay any run step by step.
