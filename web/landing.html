Architecture

Inside the agent.

Start in the Workspace: add a GitHub repo or upload a manifest and scan it, or paste a red Dependabot PR URL into the console to rescue it. Scanning reads your dependency files, checks OSV.dev, EPSS and CISA KEV, and needs no API key. When you press Fix with agent, the stages below run: nothing ships until the tests pass and your code still behaves exactly as before.

Pipeline stages

🔌

Connect

Resolves the Nemotron model for each tier from the provider's /models catalog, or uses the ones pinned in Settings (or MODEL_*). On this server: nano auto, super auto, ultra auto.

📦

Check out

Clones the project's GitHub repository (or copies a bundled sample project). Fix mode needs a pinned requirements.txt and a pytest suite.

🛰️

Scan OSV.dev

Every pinned package is queried against the open-source vulnerability database for real CVEs and GHSAs.

⚡

Triage nano

Decides which advisories your code actually reaches, so the plan focuses on what matters.

🔎

Research Tavily

Searches for changelogs and migration guides for each upgrade. The sources are kept as evidence.

🧭

Plan super

Picks the safe target version for each package and flags breaking upgrades.

🔒

Behaviour lock super

Before anything changes, Nemotron writes calls into your own functions and a fixed harness records what they return, twice, dropping anything non-deterministic. After the repair every call must return the same thing; a difference goes back to the repair model even when pytest is green. It protects repos with few or no tests.

🧪

Upgrade & test

Installs the new versions in an isolated venv and runs your pytest suite.

🛠️

Repair super → ultra

Failures go back to Super with the stack trace. If it keeps failing, the job escalates to Ultra, up to the configured maximum fix attempts.

🚀

Pull request

Green tests produce the diff, the cited evidence and a PR description, and a real GitHub PR if GITHUB_TOKEN is set. In rescue mode the fix is pushed onto the existing Dependabot PR instead.

FAQ

Good questions.

Does it change my code or just versions?

Both. When an upgrade breaks an API, the agent edits the call-sites and re-runs the tests until they pass.

What if it can't get the tests green?

The run ends as "needs review". You still get the partial diff, the test output and the research, but no PR is opened.

Which LLM provider does it use?

Any OpenAI-compatible endpoint serving Nemotron: Nebius Token Factory, NVIDIA NIM or OpenRouter. An admin sets the base URL, key and models on the Settings page (stored encrypted), or with NEBIUS_BASE_URL and NEBIUS_API_KEY in .env.

Is running untrusted repos safe?

Scanning never runs repository code: it only downloads and parses manifest files, so it works for any public GitHub repo. Fix mode runs the repo's tests in a throwaway venv, and public servers can switch it off for remote repos with ALLOW_REMOTE_REPOS=0, leaving only the sample projects fixable.

Which files can a scan read?

requirements.txt, pyproject.toml (PEP 621 and Poetry), poetry.lock, uv.lock and Pipfile.lock. Only exact pins can be looked up; unpinned dependencies are listed but not checked, and -r includes are not followed.

Can I audit what the agent did?

Yes. Every event is written to a JSONL log. Open the Runs page to replay any run step by step.
